# 06. UI/UX 전체 명세

> 대상: 기업·대학 지원자의 1:1 면접 연습. 한국어 우선, PC·모바일 반응형, 접근성(WCAG 2.1 AA 지향). UI는 9화면 해시 라우터(`public/index.html`, `app.js` 엔트리 + `core/`·`screens/`·`ui/` ES 모듈, `styles.css`; WP-D1~D7·D9로 구현, D8 접근성 QA 미착수)이며 **재작성이 아니라 점진 개선**이 기본이다(E2E 계약 셀렉터는 §11).
> 이 명세의 "목표"는 구현 완료를 뜻하지 않는다. 현재 상태는 PROJECT.md §7.

## 1. UX 원칙

1. **한 화면 한 결정.** 입력·설정·진행을 한 화면에 섞지 않는다(PROJECT.md §3).
2. **근거가 먼저.** 모든 질문·관찰 옆에 "무엇에 근거했는지"(지원서 문장·기관 자료·답변 인용)를 보여 준다. 근거가 없으면 "근거 없음/판단 보류"를 숨기지 않는다.
3. **정직한 라벨.** Mock·폴백·규칙 기반·합성 샘플을 항상 구분 표시한다. 실제 AI로 오인시키는 표현·가짜 파형·가짜 아바타 금지.
4. **한 번에 하나의 행동.** 피드백은 "실제로 한 말 → 부족한 부분 → 다음에 바꿀 행동 **하나** → 새 질문으로 재연습"(PROJECT.md §2.6). 총점·순위·백분위·장식 그래프 없음.
5. **안전한 기본값.** 기본 설정으로 바로 시작 가능, 위험한 선택(외부 전송·삭제)은 명시적 확인.
6. **복구 가능.** 모든 실패는 원인·다음 행동을 보여 주고(재시도/텍스트로 계속/나중에), 입력은 잃지 않는다.
7. **조용한 연습실.** 면접실은 질문·타이머·답변 영역만. 설명 문구·부가 패널·장식 최소화.

### 2.2 흐름과 단계 표시
- S2→S3→S4는 상단 **스테퍼**(① 지원 정보 ② 근거 확인 ③ 면접 설정)를 표시한다. S5 이후는 스테퍼 대신 면접실 UI.
- 새로고침·직접 URL 진입: 서버 상태에서 복원한다(진행 중 세션 있으면 S1에 "이어서 하기" 카드, S5 직접 진입 시 세션 조회 후 복원, 없으면 S1로 이동 + 안내 토스트). 현재는 클라이언트 상태에 의존하므로 **복원 로직이 WP-D 범위**다.
- 라우트 가드: 조건 불충족 시 이전 단계로 보내고 이유를 토스트/배너로 설명("근거를 먼저 승인해야 면접을 시작할 수 있습니다").
- 화면 전환 시 `<h1>`에 포커스, `document.title` 갱신, 스크린리더용 `aria-live` 폴라이트 안내.

### 2.3 전역 크롬
- **앱바:** 브랜드, 주요 이동(대시보드·기록·데이터), **모드 칩**(§5.2), 이용 안내. 관리자 메뉴는 앱바에 노출하지 않고 `#/admin` 직접 접근만(일반 사용자 화면에 노출 금지).
- **푸터:** "근거 기반 참고 코칭이며 합격 예측이 아닙니다 · 만 19세 이상 · 현재 평가는 규칙 기반입니다"(평가기가 바뀌면 문구도 실제에 맞춰 갱신).

## 5. 상태 체계

### 5.1 모든 화면의 공통 7상태
| 상태 | 표시 | 규칙 |
|---|---|---|
| loading | 스켈레톤/문구 "불러오는 중…" | 800ms 이상 걸릴 때만 스켈레톤, 입력은 비활성 |
| empty | 원인+다음 행동 버튼 | 예: 기록 없음 → "첫 연습 시작" |
| error | 인라인 `role="alert"` + 재시도 | 원인(네트워크/인증/서버/한도) 구분, **입력 보존** |
| blocked | 이유와 해결 경로 | 예: "근거를 승인해야 시작할 수 있습니다" |
| degraded | 앰버 배너 | 폴백·Mock 대체·일부 기능 비활성. 무엇이 대체됐는지 명시 |
| success | 토스트/인라인 확인 | 저장·삭제·승인 |
| stale | "n일 전 자료" 배지 | 출처 신선도(`aging/stale/unknown`) |

### 5.2 모드·평가기 라벨 (항상 정확해야 하는 표시)
- **앱바 모드 칩:** `Mock 모드 · 외부 전송 없음` / `일부 실모델` / `실모델` / `서버 연결 실패`. 데이터는 `GET /providers/status`(인증 필요; 비인증 시 `health.provider.selected`만).
- **설정 화면 요약:** operation별 `꼬리질문: DeepSeek | 주장 추출: Mock …` + 차단 사유(03 §4 `reason` 코드→한국어 문구 매핑 표를 `public/core/copy.js`에 둠(구현됨, WP-D2)).
- **면접 중:** 폴백 시 해당 질문에 배너. 실제 사용 공급자는 `provider_trace`의 값.
- **보고서:** 평가기 칩 `규칙 기반 참고 관찰`(현재) — LLM 평가를 연결해도 사람 평가 전에는 `Claude 분석 · 검증 중`으로 표기, "정확한 AI 평가" 금지.
- **합성 샘플:** 샘플을 불러오면 입력란 위에 `합성 샘플` 배지, 샘플 답변을 넣으면 답변란 옆에 배지.

## 6. 문구 규칙 (마이크로카피)

- **어조:** 시스템 문장은 합쇼체("~합니다"), 사용자 요청은 "~해 주세요". 짧게. 한 문장 한 정보. 영어 약어 최소화(필요 시 첫 등장에 풀이).
- **금지 표현:** 합격/불합격 가능성·확률·예측, "AI가 정확히 평가", 점수 순위·백분위, 거짓말/성격/감정/외모 분석, "검증된 AI 채점"(검증 전). 린트: `public/`·API 응답 문구에서 위 키워드 검사 테스트(E2E의 "합격 예측 문구 없음" 확장).
- **필수 라벨(고정 문구):** `규칙 기반 참고 관찰`, `Mock 모드 · 외부 전송 없음`, `판단 보류`, `합성 샘플`, `거짓 여부를 판정하지 않습니다`, `단일 재연습 비교는 학습 효과를 입증하지 않습니다`.
- **출처 상태 라벨(고정):**

| `status` | 라벨 | 설명(툴팁) |
|---|---|---|
| `official_verified` | 공식 자료 확인 | 서버가 공식 도메인에서 수집·발췌 확인(수집기 구현 후에만 사용) |
| `user_supplied` | 사용자 제공 | 직접 입력·업로드. 진위 미확인 |
| `monthly_trend` | 월간 트렌드(보조) | 관리자 검수 자료. 기관 공식 요구가 아님 |
| `unverified` | 확인되지 않음 | 근거 부족 |
| `unavailable` | 수집 실패 | 접속 불가·거절·시간 초과 |
| `stale` | 오래된 자료 | 365일 초과 등 |
| `conflict` | 내용 충돌 | 서로 다른 값 — 어느 쪽도 사실로 단정하지 않음 |

- **오류 문구 구조:** `무슨 일이 일어났는지 → 입력은 안전하다/아니다 → 다음 행동`. 예: "답변 제출이 늦어지고 있습니다. 입력한 내용은 그대로 있습니다. 다시 시도하거나 잠시 후 이어서 하세요."
- **폴백 문구:** "AI 응답을 받지 못해 기본 질문으로 이어갑니다."(공급자 이름 노출은 설정/상세에서).

## 7. 화면별 명세

각 화면: 목적 · 레이아웃 · 구성요소 · 상태 · 데이터/API · 수용 기준. DOM id는 §11 계약.

### S1 대시보드 (`dashboard`)
- **목적:** 여정 선택(기업 취업 / 대학 입학), 이어하기, 최근 연습.
- **레이아웃:** 상단 한 줄 가치 문구(≤2줄) → 여정 카드 2개(`#journeyCompany`, `#journeyUniversity`) → "이어서 하기"(진행 중 세션이 있을 때) → 최근 연습 3건 → 샘플로 체험하기 링크(`DEMO_FIXTURES=on`).
- **상태:** 처음 사용자(empty: 안내+시작), 이어하기 있음, 서버 연결 실패(error).
- **데이터:** `GET /sessions`, `GET /providers/status`.
- **금지:** 긴 마케팅 문구, 개발자용 API 상태 칩(모드 칩만).
- **수용:** 첫 화면에서 한 번의 클릭으로 S2 진입, 진행 중 세션이 있으면 S1에서 이어하기 가능.

### S2 지원 정보·서류 (`application`)
- **목적:** 기관·직무/학과·서류 입력. 어떤 정보가 어디에 쓰이는지 명확히.
- **구성(위→아래):**
  1. 스테퍼 ①. 기업=`기업 지원 정보`, 대학=`대학 지원 정보`(제목은 E2E가 확인).
  2. **합성 샘플 불러오기** 버튼(데모 모드): 클릭 시 입력란 채움 + `합성 샘플` 배지.
  3. 기본: 기관명, 직무(기업)/학과·전형(대학).
  4. **공고·모집요강** 본문 또는 파일.
  5. **자기소개서·지원서** 본문 또는 파일(주장 추출 대상). 도움말: "본인이 쓴 경험·성과 문장을 붙여넣으세요."
  6. **파일 업로드(`DocumentCard`)**: 종류 선택(공고/자소서/이력서/기타) → 추출 → 결과 카드(성공 시 미리보기·글자 수·`추출 텍스트` revision, 편집 가능 / 실패·스캔 PDF 시 "텍스트를 직접 붙여넣어 주세요"). 5MB 안내는 **실제 한도와 일치**(BUG-9).
  7. 출처 URL(선택, 최대 3). 문구: "서버는 URL에 접속하지 않고 출처 기록만 합니다"(수집기 구현 후 문구 갱신).
  8. 경험 메모(선택, 최대 3줄).
  9. 하단 고정 행동: `근거 확인하기`(primary), `자료 없이 일반 연습`, `취소`.
- **연령·처리 안내(오버레이, 첫 실데이터 입력 전 1회):** "만 19세 이상입니다"(체크) + 처리 요약 3줄(저장 방식·보존 30일·외부 AI 사용 여부=현재 모드 기반 문구, 03 §5) + `동의하고 계속`. 미동의 시 샘플로 체험만 가능. `POST /consents`.
- **상태:** 추출 중(`DocumentCard` loading), 추출 실패, 크기 초과, PII 후보 감지 토스트("개인정보 후보를 마스킹했습니다 — 완전 익명화는 아닙니다"), 서버 오류(입력 보존).
- **데이터:** `POST /consents`, `POST /profiles`, `POST /profiles/:id/documents`, `PATCH /documents/:id`, `GET /fixtures`.
- **수용:** 기업·대학 2경로 모두 입력→S3 이동. 지원서 본문이 있으면 S3에서 주장이 보인다. 파일 실패 시 입력 보존과 붙여넣기 안내. 연령 미확인 상태로 실데이터 제출 불가(428 처리).

### S3 근거 확인·승인 (`evidence`)
- **목적:** 서버가 추출한 근거를 사용자가 확인·수정·승인. 승인 전 면접 시작 불가.
- **구성:** 스테퍼 ②. 섹션 4개(접기/펼치기, 모바일은 아코디언):
  1. **지원서 주장·공백**: `ClaimItem` 목록(원문 인용·위치·공백 칩, **이 질문에서 제외** 토글). 없으면 "경험·성과 서술 문장을 찾지 못했습니다. 일반 질문으로 진행합니다." 고정 문구: "거짓 여부를 판정하지 않습니다. 문장에 근거가 적혀 있는지 보고 빠진 정보를 묻습니다."
  2. **공식·출처**: `SourceChip` 상태별 카드(URL, 발행일·확인일, 신선도, 충돌). 수집기 전에는 `official_verified`가 나올 수 없음을 도움말로 설명.
  3. **공고 키워드·핵심 가치**: 기관 프로필(확인된 요구 / 형식 / 평가 가능·불가 영역) — "기관의 비공개 채점기준을 아는 것처럼 표현하지 않습니다".
  4. **월간 트렌드(보조)**: 공개본 최대 3개, 라벨 `월간 트렌드(보조)`, 없으면 "승인된 월간 역량이 없습니다".
  5. **질문 계획 미리보기**(`GET /profiles/:id/plan`): 질문별 근거 링크.
- **행동:** `이 내용으로 승인`(primary), `지원 정보 수정`. 확인 메모(선택).
- **상태:** 불러오는 중, 분석 실패→"일반 기준으로 진행" 배지, 근거 없음, 출처 충돌 경고.
- **수용:** 승인 전 S4 진입 시 가드 메시지. 제외한 주장은 면접 질문에서 빠진다. 모든 근거에 인용+위치+상태 라벨.

### S4 면접 설정 (`setup`)
- **목적:** 최소 설정 후 시작. 기본값으로 즉시 시작 가능.
- **구성:** 스테퍼 ③. 시간(5/10/15분, 문항 수 병기), 면접관 성향(친절/일반/논리 검증), 답변 방식(텍스트 / 음성 인식 / 녹음 전사), 면접관 음성 듣기(TTS) 토글(지원 시), **블라인드**(안전하게 동작할 때만 선택 노출·"완전하지 않을 수 있음" 고지). **면접 유형**은 기본 `일반·인성`만 보이고 나머지는 `고급(실험)` 접힘 안에(DEBT-8).
- **요약 카드(`#setupSummary`):** 근거 승인 상태, 사용할 근거 수, **외부 AI 사용 요약**(operation별 live/mock + 차단 사유), 예상 소요.
- **금지:** 예산 수치·API 용어·과도한 설정.
- **수용:** 기본값으로 `면접 시작` 한 번으로 S5 진입. 요약이 실제 모드와 일치.

### S5 실전 면접실 (`room`)
- **목적:** 질문 하나에 집중해 답한다.
- **레이아웃(데스크톱):** 상단 바(`LIVE`/`일시정지` 상태, 남은 시간 `#clock`, 진행 막대) → 질문 카드(`#roomTitle`, h1) → (있으면) **근거 칩** "지원서 근거: “…” (원문 위치 a–b)"(`#roomHint`) → 면접관 응답 영역(`#aiReply`) → 답변 영역(`#answerText`, 글자 수 `n/4000`) → 입력 도구(음성) → 행동(`답변 완료`, `일시정지`, `면접 종료`) → 보조(`질문 듣기`, `질문 복사`).
- **모바일:** 행동 버튼을 하단 고정 바로, 질문 카드는 접을 수 있는 긴 인용(근거 칩은 펼침), 키보드 올라와도 `답변 완료`가 가려지지 않게(`env(safe-area-inset-bottom)`, 뷰포트 높이 대응).
- **상태:** 제출 중(버튼 비활성+"면접관이 답변을 확인하는 중…"), **폴백 배너**, 일시정지(오버레이: 재개/종료), 시간 임박, 서버 오류(재시도·입력 보존), 연결 끊김(세션 복원 시도), 제출 불가(빈 답변 안내).
- **종료:** 확인 다이얼로그(`면접을 종료하면 지금까지의 답변으로 보고서를 만듭니다`) → 보고서 대기(스피너+"보고서를 만드는 중") → S6.
- **정직한 표시:** 사람 같은 아바타·가짜 파형 금지. 면접관은 텍스트 말풍선(+선택적 TTS).
- **수용:** 질문은 한 번에 하나, 타이머는 서버 시계 기준(새로고침해도 복원), 일시정지/재개 동작, 폴백 시 배너, 음성 실패 시 텍스트로 계속.

### S6 근거 기반 코칭 (`feedback`)
- **목적:** 한 번에 **바꿀 행동 하나**를 확실히 전달하고 재연습으로 연결.
- **구성(위→아래):**
  1. 헤더: 평가기 칩(`규칙 기반 참고 관찰`), 면접 유형, 루브릭 버전. 한 줄 고정 문구: "각 수준은 해당 답변에서 관찰된 정도이며 합격 가능성이 아닙니다."
  2. **가장 먼저 바꿀 것 1개**(강조 카드): `실제로 한 말`(인용) → `부족한 부분` → `다음 행동 1개` → `[이 역량으로 새 질문 재연습]`(primary).
  3. **지원서 주장과 실제 답변**(`claim_links`): 주장 문장 ↔ 답변 발췌 나란히, 질문되지 않은 주장은 "이번 면접에서 질문되지 않았습니다". 고정 문구: "사실 여부를 판정하지 않습니다."
  4. **차원별 상세**(접기): 수준 `n / 4` 또는 `판단 보류`(사유), 관찰, 인용 목록(`.evidence q`), `전사 교정`·`이의 제기`.
  5. **기관 요구와 답변의 연결**(있을 때): 관찰/미관찰.
  6. 부가: 내보내기, 이 세션 삭제.
- **금지:** 총점·종합 등급·순위·백분위·합격률·장식 그래프.
- **상태:** 생성 중(폴링, 최대 대기 안내), 생성 실패(`status:'failed'`→"답변은 보존되어 있습니다. 다시 시도"), 판단 보류 많음(안내: 답변이 더 필요).
- **수용:** 모든 관찰에 인용이 붙는다, 평가기 칩이 `evaluator` 값과 일치, 재연습 CTA가 한 번에 S7로.

### S7 새 질문 재연습·비교 (`repractice`)
- **목적:** 같은 역량을 묻는 **다른 질문**에서 두 번째 답변을 받아 나란히 비교.
- **구성:** `이전 질문`/`지금 질문` 2열(모바일은 위아래), 이전 답변 발췌, `시작`(`#startRepracticeBtn`) → 90초 면접실(S5 재사용) → 종료 후 비교(`#comparisonBox .comparison`):
  - 결과 라벨: `관찰된 변화` / `뚜렷한 변화 없음` / `판단 보류`(+사유: 동일/유사 질문, 근거 부족, 루브릭 불일치) + 한 줄 요약.
  - 두 답변의 인용을 같은 형식으로 병렬 표시.
  - **고정 주의문:** "단일 재연습 비교는 학습 효과를 입증하지 않습니다."
  - 행동: `다른 역량으로 다시`, `보고서로 돌아가기`, `한 번 더 다른 질문으로`.
- **수용:** 두 질문이 실제로 다르고 같은 역량·루브릭, 판단 보류 사유가 보인다, 장식 성장 수치 없음.

### S8 기록·데이터 (`history`)
- **목적:** 이전 기록 열람, 내보내기, 삭제, 처리 안내 확인.
- **구성:** 세션 목록(유형·날짜·상태, 보기/내보내기/삭제), `전체 삭제(계정 데이터)`(위험 다이얼로그, 확인 문구 입력), **데이터 처리 패널**(저장 항목·보존 30일·삭제 범위·외부 전송 여부 = 실제와 일치), 모드 상세(공급자 상태, 인증 사용자만), 월간 트렌드 조회(분야·월 선택, 공개본만).
- **전후 이력:** 같은 루브릭·같은 질문 조건에서만 이전/이후를 묶어 표시. 다른 모드·루브릭 점수를 한 줄로 잇지 않는다(문구 고정).
- **상태:** 기록 없음(empty), 삭제 중/완료 토스트, 서버 재시작으로 사라진 기록(영속 도입 전까지 안내 문구: "서버 재시작 시 기록이 사라질 수 있습니다").
- **수용:** 삭제 후 목록·보고서·비교·내보내기가 모두 404/사라짐(E2E+API 테스트).

### S9 관리자 (`admin`)
- **목적:** 월간 핵심 역량 검수·승인·버전 관리(운영자 전용).
- **게이트:** `ADMIN_TOKEN` 미설정 → "관리 기능이 꺼져 있습니다"(입력 비활성). 설정됨 → 토큰 입력(`#adminTokenInput`)→ 검증.
- **구성:** 분야(기업/대학)·연월 선택 → 항목 편집기(최대 3개, **출처 ≥1·코멘트 필수** 검증 즉시 표시) → 검토 체크리스트(출처·발행일·반복성·편향/충돌 확인 체크) → `초안 저장` → 버전 이력(상태: 초안/공개/롤백) → `공개`·`롤백`·`공개 중단`(확인 다이얼로그). 공개본 미리보기("사용자에게는 이렇게 보입니다").
- **상태:** 인증 실패(403 안내), 한도(3개 초과) 오류, 저장 성공.
- **수용:** 출처 없는 공개 불가, 일반 사용자 화면에 관리자 UI 노출 없음, 롤백 시 새 버전 기록.

### 오버레이·보조 화면
- **이용 안내 패널:** "하는 일/하지 않는 일" 2열(현행 유지), 현재 평가기·모드·만 19세 문구는 실제 값과 동기.
- **접속 토큰 다이얼로그:** 401 시 1회 질문, 저장은 `localStorage`(한계 안내), 취소하면 같은 페이지에서 재질문하지 않음(현행).
- **면접 종료/삭제 확인:** 위험 행동은 `danger` 스타일, 기본 포커스는 취소.

## 8. 접근성 (WCAG 2.1 AA 지향) — 수용 기준

- 모든 입력에 가시 라벨, 오류는 `aria-describedby`+`role="alert"`, 필수/선택 표기.
- 키보드만으로 전 흐름 가능: 탭 순서가 시각 순서와 일치, 포커스 링 3px 유지, 다이얼로그 포커스 트랩·ESC·반환 포커스, 라우트 전환 시 `<h1>` 포커스.
- 색만으로 의미 전달 금지(칩에 텍스트·아이콘). 본문 대비 4.5:1, 큰 글자 3:1. `prefers-reduced-motion`·`prefers-contrast: more` 준수.
- `aria-live`: 질문 변경·면접관 응답·상태 변경은 polite, 오류는 assertive. 타이머는 1분/10초만 낭독.
- 터치 영역 ≥44px, 확대 200%에서 가로 스크롤 없음(레이아웃 깨짐 금지), 텍스트 크기 `rem`.
- 스크린리더: 인용은 `<q>`/`blockquote`, 진행률은 `role="progressbar"`+값, 아이콘은 `aria-hidden`.
- 자동 점검: E2E에 `axe` 대체가 없으므로(의존성 금지) 체크리스트 기반 수동 점검표를 `08`에 두고, 가능한 항목(라벨 존재, 대비 계산, 포커스 이동)은 E2E 코드로 검사한다.

## 10. 음성 UX (STT/TTS)

**입력 상태 머신(`VoiceControl`)**
`idle` →(권한 요청)→ `permission` →(허용)→ `recording`(경과 시간·최대 120초 표시) →(정지)→ `uploading`(전사 중) →(성공)→ `review`(전사문을 답변란에 채우고 **확인·교정 후 제출**) / `error`(권한 거부·녹음 불가·무음·너무 짧음·한도·서버 실패) → 항상 **텍스트 입력으로 계속** 가능.
- 첫 사용 전 안내: "녹음은 전사를 위해서만 전송되며 저장하지 않습니다."(실제 동작과 일치).
- 전사 결과에 PII 후보가 있으면 `pii_warnings` 안내, 사용자가 교정 가능(`전사 교정`은 새 revision).
- 마이크 없음/브라우저 미지원은 버튼 비활성+이유 표시. 녹음 중 파형은 **실제 입력 레벨**일 때만(가짜 애니메이션 금지).

**TTS:** `질문 듣기`는 현재 질문/직전 발화만 재생. ElevenLabs 사용 시 사전에 "합성 음성입니다" 표기, 실패/차단 시 브라우저 TTS로 자동 대체하고 배너 없이 조용히 전환(기능 저하만 표시). 자동재생 금지(사용자 클릭 시), 정지 버튼 항상 제공, 속도 조절은 Could.
