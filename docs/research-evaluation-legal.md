# Intervu 평가 신뢰성·개인정보·운영 경계 연구

조사일: 2026-10-23 (Asia/Seoul). 이 문서는 공개 원문에 대한 연구와 제품 설계 제안이다. 법률 적용 판단은 실제 운영 주체·이용약관·API 계약·데이터 흐름에 따라 달라지므로 출시 전 검토 항목을 따로 표시한다. 아래 수치형 품질 기준과 보존 기간은 **설계 목표**이며, 이미 측정한 성능이나 법정 기간이 아니다.

**통합 설계 우선:** 이 연구의 후보 정책과 충돌하면 `master-plan.md`의 확정 범위 및 `implementation-spec.md`의 계약을 따른다. 통합 시 채택한 방향은 만 19세 이상, 원문·보고서 기본 30일/선택 보관 최대 180일, 애플리케이션 로그 14일/식별자 제거 집계 90일/백업 최장 30일 목표다. 아래 90일 전사·30일 운영 로그 등은 비교용 연구 제안으로 남기며 구현 기본값으로 사용하지 않는다. 공급사 계약 확인 및 별도 법정 보존 의무 검토는 계속 출시 게이트다.

## 1. 결론과 근거

Intervu는 채용 의사결정 시스템이 아니라 **답변의 관찰 가능한 행동을 연습하고 개선하는 개인용 코칭 서비스**로 설계한다. 기업 합격 확률, 인성 등급, 정직성, 잠재력, 얼굴·음성으로 추정한 감정/성격은 제공하지 않는다. 실제 합격과의 종단 검증 데이터가 없으므로 ‘면접점수 85점 = 합격 가능성 85%’와 같은 연결은 성립하지 않는다.

미국 OPM은 직무 분석에 연결한 질문, 공통 평가 기준, 행동 수준의 기준점을 갖춘 구조화 면접을 권고한다. 이를 Intervu의 질문 설계와 평가 기준의 출발점으로 삼되, 인간이 수행한 채용 면접의 타당도가 한국어 생성형 AI 코치에 그대로 이전된다고 주장하지 않는다. [OPM 구조화 면접 안내](https://www.opm.gov/policy-data-oversight/assessment-and-selection/structured-interviews/), [실무 가이드 PDF](https://www.opm.gov/policy-data-oversight/assessment-and-selection/structured-interviews/guide.pdf)

얼굴 움직임과 감정의 대응은 문화·상황·개인에 따라 달라진다는 연구 검토가 있다. 이것이 모든 비언어 행동 관찰을 금지한다는 뜻은 아니지만, 얼굴 표정에서 감정과 면접 적합성을 확정하는 기능을 정당화하지 않는다. 카메라는 MVP에서 제외한다. [Barrett 외, 2019, 원논문 초록](https://www.psychologicalscience.org/journals/pspi/1529100619832930/)

LLM 평가자는 위치, 장황함, 자기 모델 계열 선호 등의 편향과 추론 한계가 있다. 챗봇 답변 선호 연구의 높은 인간 일치도를 면접 평가 정확도로 광고해서는 안 된다. 따라서 점수만 출력하는 프롬프트가 아니라 증거 검증·기권·인간 기준 평가 세트를 갖춘다. [Zheng 외, NeurIPS 2023 원논문](https://arxiv.org/abs/2306.05685)

### 2.2 공통 행동 루브릭 v1

각 차원은 1~4 정수 또는 `insufficient_evidence`. 0점은 쓰지 않는다. 점수는 해당 답변에서 보인 수준일 뿐 잠재 역량이 아니다. 빈 답변·STT 손상·관찰 기회 없음은 낮은 점수 대신 기권한다.

| 차원 | 1: 미흡한 관찰 | 2: 부분 관찰 | 3: 충분한 관찰 | 4: 확장된 관찰 |
|---|---|---|---|---|
| 질문 적합성 | 다른 질문에 답함 | 일부 요구만 다룸 | 핵심 요구를 직접 다룸 | 핵심 요구와 중요한 조건·제약까지 다룸 |
| 행동·근거 구체성 | 추상 주장만 존재 | 사례 있으나 본인 행동/결과 불명확 | 본인 행동과 결과·근거가 연결됨 | 판단 이유·확인 방법·기여 경계를 함께 제시 |
| 논리·대안 | 결론과 이유가 연결되지 않음 | 이유 있으나 주요 가정이 빠짐 | 주장·이유·결론이 일관됨 | 대안·절충·한계에 대해 근거 있게 비교 |
| 직무 관련 이해 | 검증 가능한 핵심 개념 오류 | 일부 정확하나 중요한 조건 누락 | 시나리오에 적절한 지식/절차 적용 | 위험·트레이드오프와 확인 절차까지 설명 |
| 성찰·개선 | 질문이 요구한 성찰이 없음 | 일반적인 교훈만 있음 | 구체적 교훈과 다음 행동 있음 | 후속 적용/검증 계획과 한계를 함께 설명 |

기술 지식의 채점은 신뢰 가능한 기준 자료와 담당자의 검토가 있는 질문에만 적용한다. 기준 자료 없는 특수 직무는 직무 지식 차원을 `not_assessed`로 표시한다. STAR 형식을 강요하지 않는다. 사실을 꾸미거나 숫자를 만들어내라는 개선안도 금지한다. ‘수치가 있다면 출처와 함께, 없다면 관찰 가능한 변화로 설명’하도록 코칭한다.

종합점수는 MVP 기본 화면에서 숨기고 차원별 행동 수준을 보여준다. 성장 차트는 동일 루브릭 버전의 차원별 중앙값과 평가 답변 수를 표시한다. 관찰 기회가 다른 차원을 묶거나 결측치를 0점 처리하지 않는다. 평가자는 친절/일반/압박 스타일 설정을 받지 않는다. 스타일은 질문 표현을 바꾸며 평가 기준은 바꾸지 않는다.

### 2.3 면접 유형별 추가 관찰

- **일반 인성·경험:** 책임 범위, 구체적 행동, 성찰. ‘착함/충성심/조직 순응’ 추론 제외.
- **직무·상황:** 요구조건 확인, 대안 선택, 검증 방법. 실제 경험 여부와 가상 문제 해결을 구분.
- **블라인드:** 별도 면접 형식보다 개인정보 비노출 정책으로 구현. 본인이 제공한 신상도 평가 컨텍스트에서 제거. 학교·지역 언급은 채점 감점 대신 별도 주의 알림으로 제공.
- **PT:** 주장의 구조, 주어진 자료의 사용, 가정·대안·시간 배분. 슬라이드 미관과 답변 내용 분리. PT 준비 시간이 다른 세션의 총점 직접 비교 금지.
- **토론:** 상대의 실제 발언을 정확히 반영했는지, 근거 기반 반론, 의견 수정·합의 정리. AI가 반박 기회를 주지 않았다면 해당 차원은 관찰 불가. AI 참가자는 점수·예상 약점을 볼 수 없게 한다.
- **다대다:** 사용자별 발언 기회를 기록하고 분모로 공개. AI만 여러 명인 연습은 실제 인간 집단의 사회적 역동성을 검증하지 못하므로 ‘다자 상황 시뮬레이션’으로 명시한다.

### 2.4 평가 파이프라인과 데이터 계약

1. 세션 종료 후 전사 확정. 음성 인식 오류 수정은 원본 전사와 별도 버전으로 기록한다. 사용자가 내용을 개선해 수정한 답변은 실시간 수행 점수를 덮어쓰지 않고 ‘수정 답변 연습’으로 구분한다.
2. 개인정보 마스킹 → 질문별 답변 구간 확정 → 적용 가능한 루브릭 선택.
3. 평가 모델에 고정 루브릭, 질문 의도, 사용자 발화, 검증된 근거 자료만 전달. 생성 인터뷰어의 내부 판단/점수·칭찬은 전달하지 않는다.
4. 각 평가 주장에 정확한 `turn_id`, `start_char`, `end_char`, 원문 인용을 요구한다. 서버에서 실제 부분 문자열 일치·사용자 발화 여부·길이·차원 enum·점수 범위를 검증한다.
5. 증거가 없으면 기권. 유효하지 않은 인용은 최대 1회 수정 요청 후 해당 항목을 숨긴다. 전체 실패는 ‘평가 준비 실패, 재시도’ 상태로 표시하고 가짜 점수를 채우지 않는다.
6. 사용자가 확인할 핵심 강점 최대 2개, 개선 목표 최대 2개, 각 목표별 재질문 1개 생성. 개선 답변 예시는 사용자가 제공한 사실만 재구성한다.
7. 이의 제기에서 `오인식/사실오류/근거부족/부적절함` 선택 → 문제 항목·버전 보존 → 재평가/운영자 검토. 원 결과는 변경 이력으로 추적 가능하게 한다.

```json
{
  "evaluation_id": "uuid",
  "session_id": "uuid",
  "transcript_version": 1,
  "rubric_version": "behavioral-ko-v1",
  "model_snapshot": "provider-and-model-id",
  "prompt_version": "eval-v1",
  "dimension": "evidence_specificity",
  "level": 3,
  "status": "scored",
  "evidence": [{"turn_id": "t4", "start_char": 0, "end_char": 18, "quote": "실제 부분 문자열"}],
  "observation": "사용자가 말한 행동과 결과의 연결을 설명",
  "limitation": "경험의 사실 여부는 확인하지 않음",
  "next_action": "선택한 방법의 이유를 한 문장 추가",
  "abstention_reason": null
}
```

이 JSON은 구조 예시이며 인용 위치 값은 실제 입력으로 검증해야 한다. 모델이 자기 보고한 ‘신뢰도 95%’를 UI에 노출하지 않는다. 대신 `충분한 근거/제한된 근거/판단 보류`를 증거 수·입력 완전성·규칙 검증에 따라 표시한다. 다른 모델 두 개의 일치도도 객관적 진실의 증명은 아니다.

## 3. 평가 신뢰성 검증 계획

아래는 제안 실험 설계다. 작은 초기 표본으로 직군 전체, 장애 유형 전체, 합격 예측의 타당성을 주장할 수 없다.

### 3.1 출시 전 정량·정성 게이트

| 항목 | 최소 검증 방법 | 제안 통과 기준 및 실패 시 조치 |
|---|---|---|
| 내용 타당성 | 목표 직군 실무자·면접 경험자 3명 이상이 질문과 역량 매핑 검토 | 부적절하거나 기준 없는 질문 제거; 검토 이력 없는 질문은 정량 지식 채점 불가 |
| 인간 기준 세트 | 동의받은 한국어 답변 최소 200개, 최소 50명. 질문군·길이·성과 설명 수준 다양화 | 사용자 단위로 개발/검증 분리. 2명 독립 평정 후 불일치 조정, 일부 제3자 검토 |
| 평정 일치 | 차원별 quadratic-weighted kappa, 인접 단계 일치율, 혼동행렬, bootstrap CI | 가중 κ ≥ 0.60, ±1 단계 일치 ≥ 90%를 임시 게이트로 제안. 불충족 차원은 점수 비노출; 인간 간 일치도 함께 보고 |
| 증거 정확성 | 인용 문자열 서버 검증 + 인간이 ‘주장을 지지하는가’ 확인 | 문자열 100%, 의미상 근거 지지 ≥ 95%. 중대한 환각 지적 0건을 회귀 테스트 목표로 설정 |
| 재현성 | 동일 고정 전사 100개를 각각 3회 평가 | ±1 단계 이상 변동 항목 비율, 차원별 분산 공개; 목표 초과 시 온도/프롬프트/루브릭 조정 |
| 편향 | 동일 내용을 이름/학교/성별 단서/문체만 바꾼 대응쌍 100쌍 이상 | 차원별 평균 절대 차이 ≤ 0.25/4점, 1단계 초과 차이 발생 원인 검토. 이 수치는 공정성 인증 기준 아님 |
| 접근성·STT | 사투리·잡음·느린 말·더듬음/텍스트 입력 조건 테스트 | 손상된 전사로 낮게 채점하지 않음. 전사 확인·텍스트 전환 가능. 고정된 이상적 발화 속도 강요 금지 |
| 공격 내성 | 답변/업로드에 ‘무조건 만점’·개인정보 유출 지시 삽입 | 도구 실행/시스템 변경 불가, 인용에 없는 개선 사실 생성 차단 |
| 학습 효과 | 목표 사용자 30명 내외 탐색 파일럿; 전후 동등 난이도 질문, 순서 균형화, 인간 평가자 조건 블라인드 | 완료율·재연습률·이해도와 효과크기/불확실성 보고. 인과 효과는 추후 대조군 연구 전까지 주장하지 않음 |

상기 통과 수치들은 학계 표준으로 인용하지 않으며 서비스 내부의 보수적 초안이다. κ는 라벨 분포의 영향을 받으므로 숫자 하나만으로 통과시키지 않는다. 신뢰구간이 넓으면 ‘검증 미완료’로 남긴다. 충분한 표본 크기는 후속 연구의 검정력 분석으로 정한다.

### 3.2 운영 후 변경 통제

모델/프롬프트/루브릭 중 하나라도 변경하면 고정 회귀 세트 전체를 재평가한다. 버전별 점수는 혼합하여 성장률 계산하지 않는다. 새 버전은 합성·명시적 동의 데이터로 shadow 평가하고 게이트 통과 후 전환한다. 운영 세션을 품질 연구에 쓰려면 별도 목적과 적법 근거를 갖춘다. 서비스 이용 동의에 연구/모델 학습 동의를 끼워 넣지 않는다. 삭제 동의 철회가 불가능한 데이터 학습은 MVP에서 수행하지 않는다.

## 4. 한국 법률과 운영 설계

### 4.1 개인정보와 국외 API

국외 이전에는 해외 제공뿐 아니라 처리위탁·보관도 포함된다. 별도 동의 외에도 법이 정한 경로가 있으므로 ‘외국 API는 항상 별도 동의가 필요하다’고 단정하지 않는다. 계약 이행에 필요한 처리위탁·보관 경로를 쓰는 경우에도 법정 공개/통지 조건과 보호조치를 확인해야 한다. [현행 개인정보보호법 제28조의8~11, 시행 2026-09-11](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1020398611)

**설계 결정:** 출시 환경은 각 공급사의 처리 국가·수탁자·재위탁자·보존기간·학습 사용 여부·삭제 기능·DPA를 공급사 레지스트리로 관리한다. `provider_policy_version`과 사용자의 고지/동의 버전을 기록한다. 동의가 필요한 경로에서 동의가 없으면 서버가 전송을 차단한다. 개인정보와 실제 음성을 공개 무료 데모/학습 사용 기본값 API로 보내지 않는다. 무료 할당량 존재와 개인정보 적합성은 별개다. 전사에서 이름을 지워도 음성 자체나 맥락으로 식별될 수 있어 익명정보라고 단정하지 않는다.

개인정보위는 서비스형 LLM 활용을 포함한 생성형 AI 생애주기별 개인정보 처리 안내서를 2025-08-06 공개했다. 서비스 제공, 품질 개선, 모델 학습을 분리하고 탈옥·데이터 오염·권리 보장까지 검토하는 근거로 사용한다. [개인정보보호위원회 공식 발표](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=11410)

### 4.2 연령과 학교 확장

만 14세 미만의 개인정보 처리에 법에 따른 동의를 받아야 할 때에는 법정대리인 동의와 확인이 필요하다. [개인정보보호법 제22조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398523)

**MVP 권고:** 만 19세 이상 개인 이용자로 제한한다. 연령 확인에 주민등록번호·신분증 수집부터 도입하지 않는다. 14세 기준은 개인정보 동의 기준이며 모든 미성년자 계약을 해결하는 기준이 아니다. 만 19세 미만 유료 구독/환불·보호자 동의는 별도 검토한다. [민법 제4~5조를 설명한 한국소비자원 자료](https://www.kca.go.kr/home/sub.do?menukey=4005&mode=view&no=1001342312)

학교 서비스 확장 시 학생, 학교, 공급사 역할·위탁 계약·교사 조회 권한·동의 철회·학생별 보존 정책부터 정한다. 학교 계정이라는 이유로 보호자가 결과에 자동 접근하게 하거나 교사가 학생 음성을 일괄 열람하게 하지 않는다.

### 4.3 AI 기본법과 실제 채용 금지

AI 기본법은 생성형 AI 결과물 표시 의무를 규정한다. 제31조 개별 조문 페이지는 시행 2026-07-21, 법률 제21311호로 확인했다. 사용 전 ‘AI 모의면접’ 안내, 화면의 AI 면접관 표시, 결과 화면/PDF의 ‘AI 생성 코칭’ 표시를 기본 적용한다. 합성 음성도 AI 음성임을 분명히 한다. [현행 제31조 제2항](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031810729), [법률 제21311호 본문: 사전고지·고영향 검토 조항](https://www.law.go.kr/lsInfoP.do?lsiSeq=282791)

고영향 AI에는 채용 등 권리·의무에 중대한 영향을 주는 판단/평가 영역이 들어간다. 개인 연습만 제공하는 Intervu의 해당 여부는 사용 맥락에 따른 **검토 필요 사항**이며 자동 면제라고 확정하지 않는다. 불명확하면 과기정통부 확인 절차를 활용한다. [고영향 AI 공식 확인 요청 창구](https://www.msit.go.kr/user/ais/requestAi.do?mId=339&mPid=11&sCode=user)

완전히 자동화된 결정에 대한 설명 요구, 일정한 경우의 거부권과 인적 개입 등은 개인정보보호법 제37조의2에 규정되어 있다. 개인 연습 피드백에 대한 구체 적용은 별도 판단이지만, Intervu는 근거 열람·이의 제기·재평가를 제품 권리로 구현한다. 채용 담당자에게 개인별 점수/순위를 제공하는 기능과 실제 선발 API는 MVP에서 차단한다. B2B 채용/입시 선발로 전환하려면 별도의 법률·타당성 검토를 통과해야 한다. [제37조의2 현행 조문](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334889)

### 4.4 블라인드 면접

채용절차법 제4조의3은 직무 수행에 불필요한 신체조건, 출신지역·혼인여부·재산, 가족 학력·직업·재산의 기초심사자료 기재 요구/입증자료 수집을 제한한다. 이를 ‘한국의 모든 면접에서 모든 학교 질문이 항상 불법’으로 확대해석하지 않는다. 법 적용범위와 공공기관별 블라인드 규칙은 별개다. [제4조의3 원문](https://www.law.go.kr/lsLinkProc.do?joNo=000403&lsClsCd=L&lsNm=채용절차의%20공정화에%20관한%20법률&mode=11), [법 적용범위](https://law.go.kr/lsInfoP.do?lsId=011990)

제품 정책은 법의 최소 기준보다 엄격하게 운영한다. 블라인드 모드는 이름·성별·나이·학교명·출신지역·가족정보를 질문/평가 컨텍스트에서 제거한다. 기관별 허용항목은 공식 모집 공고에서 확인한 `blind_policy_version`으로 별도 적용하고 출처와 날짜를 표시한다. 학과와 기술 교육 내용처럼 직무에 필요한 정보는 학교의 명성과 분리한다. 민감정보가 자발적으로 발화되면 재질문으로 확장하지 않는다.

### 4.5 저작권·기출·기업 재현

공개된 채용 페이지와 면접 후기라고 재사용 권한이 자동 부여되는 것은 아니다. 저작권법 공정 이용은 목적·저작물 종류·사용량·시장 영향을 고려한다. 상업 서비스의 문제은행 전체 복제, 유료 기출 스크래핑, 기사/교재를 토론 주제로 통째 재배포하는 방식을 기본 아키텍처로 삼지 않는다. [저작권법 제35조의5, 시행 2026-08-11](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=05&joNo=0035&lsiSeq=283335&urlMode=lsScJoRltInfoR)

출처 레지스트리에는 URL, 제목, 발행/확인일, 허용범위, 인용 구간, 라이선스/동의 상태를 저장한다. 공식 공개 공고의 사실을 짧게 정리하여 새로운 연습 질문을 만들고 ‘공식 기출’과 ‘AI 생성 예상 질문’을 명확히 나눈다. 사용자가 올린 자료는 비공개 세션 범위에서만 처리하며 서비스 공용 문제은행에 편입하지 않는다. 기업 로고·실제 임직원 이름/목소리를 복제한 면접관도 기본 제공하지 않는다. 기업 공식 서비스로 오인시키는 표현을 피한다.

## 5. 압박 면접의 안전 경계

제품 명칭은 ‘논리 검증형(압박)’으로 설명한다. 선택 전 예상 행동(짧은 반문, 근거 재확인, 시간 제약)을 고지한다. 친절/일반/논리 검증형은 질문의 난도와 정서적 모욕을 섞지 않는다.

- 허용: ‘그 근거는 무엇인가요?’, ‘다른 대안보다 나은 이유는요?’, ‘앞선 답변과 차이가 있는데 설명해 주세요.’
- 금지: 모욕·비하·외모·가족·출신 공격, 성적 질문, 실제 불합격 협박, 인격 규정, 개인 트라우마 압박, AI가 만들어낸 이력의 모순 추궁.
- 제어: 화면 중지 버튼과 텍스트/음성 ‘중지’ 명령, 즉시 일반 모드 전환. 중지 시 감점 없음. 음성 인식 실패를 대비해 버튼은 항상 존재.
- 제한: 같은 논점을 연속 추궁하는 횟수 최대 2회, 전체 세션의 검증형 꼬리질문 최대 3회라는 초기 운영 상한을 둔다. 이는 실험으로 조정할 설계값이다.
- 차단: 생성된 질문은 출력/TTS 전 규칙·안전 검사를 거친다. 부적절하면 중립 질문 템플릿으로 대체하고 이유 코드만 운영 로그에 기록한다.
- 피드백: ‘압박을 견디지 못했다’ 평가 대신 반문에 근거를 보강했는지 관찰한다. 사용자 불편 신고를 다음 세션 성격 분류에 이용하지 않는다.

## 6. 데이터 보존·삭제·보안 구현 계약

다음 기간은 제품 제안이며 법정 최소/최대 기간이 아니다. 개인정보가 불필요해지면 지체 없이 파기해야 하고, 다른 법령으로 보존해야 하는 자료는 분리 보관한다. [법제처 생활법령: 개인정보 파기](https://easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=1&cciNo=1&cnpClsNo=3&csmSeq=1702)

| 데이터 | 기본 정책 제안 | 삭제 동작 |
|---|---|---|
| 원음 | 서버 장기 저장 OFF. 실시간 처리 메모리/버퍼만 사용 | 연결 종료·처리 완료 시 폐기. 공급사의 별도 보존은 계약/고지에서 확인 |

`DeleteRequest` 상태는 `accepted → access_revoked → primary_purged → provider_requested → backup_expiry_pending → completed`로 기록한다. 공급사 API가 개별 삭제를 지원하지 않는다면 삭제를 완료했다고 거짓 표시하지 않고 계약상 만료 시점을 분명히 한다. 삭제 요청의 식별 정보 자체도 필요 범위를 최소화한다. 법적 보존 사유와 대상이 있으면 일반 서비스 데이터와 논리/권한상 분리한다.

모든 행에 사용자/세션 소유권 검증, 서명 URL 짧은 TTL, 업로드 MIME·크기·악성 파일 제한, 전송·저장 암호화, 서비스 키 서버 전용, 관리자 최소 권한을 적용한다. 공고 URL 자동 수집은 사설 IP/메타데이터 주소 접근을 차단하고 허용된 콘텐츠만 읽는다. PDF·공고·답변 텍스트는 도구 실행 지시가 아닌 비신뢰 데이터로 취급한다. 개인정보 마스킹이 완전한 보안 경계라고 가정하지 않는다.

## 7. 구현 인수조건과 미확정 사항

개발 시작에 필요한 확정 설계: 행동 루브릭·증거 스키마·기권·버전 추적·중지 버튼·AI 표시·삭제 상태기계·수탁사 레지스트리·공개 합격예측 금지. 코드 구현 전부터 테스트용 고정 전사·공격 사례를 작성할 수 있다.

출시 전 별도 확정: 실제 법인/운영자 개인정보처리자 역할, 각 API의 국외이전 근거/처리국가/DPA/보존, 안전조치에 따른 접속기록 기간, 유료 결제 시 법정 거래자료 보존/미성년자 계약, 고영향 AI 해당성, 현재 시행령의 표시 방법 세부사항. 공식 조문 페이지 중 일부는 동적 본문이 노출되지 않아 검색 인덱스와 개별 조문 페이지를 교차 확인했다. 최신 법령 전체 적용을 법률 자문 완료로 주장하지 않는다.

평가 출시 게이트를 통과하지 못해도 면접 연습·전사·정성 피드백으로 파일럿은 가능하다. 검증하지 못한 차원은 점수만 숨겨도 문제를 완전히 해결하는 것이 아니므로, 정성 피드백 역시 근거 지지와 유해 표현 검증을 통과해야 한다.
