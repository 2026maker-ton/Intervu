# Intervu 종합 연구·프로젝트 설계서

**기준일: 2026-10-23(한국). 버전: 1.0. 상태: 구현 착수용, 시장성·성능 검증 전.**

## 0. 결론과 읽는 순서

Intervu는 **지원 공고의 확인된 조건으로 면접을 연습하고, 내 발언을 근거로 피드백을 받은 뒤, 다른 질문에서 개선을 확인하는 한국어 면접 코치**로 만든다. ‘실제 기업의 비공개 면접·채점표를 재현한다’거나 ‘객관적 합격 확률을 알려준다’는 서비스로 만들지 않는다.

초기 고객은 **만 19세 이상, 30일 내 면접을 앞두거나 집중 준비 중인 한국어 신입 구직자**다. 일반기업·공공기관을 각각 검증하되 첫 콘텐츠는 일반·공공사무 역량을 중심으로 한다. 공개 MVP는 1:1 경험·상황 면접, 성향 선택, 블라인드 옵션, 근거 기반 피드백과 재연습이다. 토론은 사용자 1명+AI 2명의 닫힌 베타로 구현하고, 기회 배분·피드백 품질을 통과한 뒤 공개한다.

이 결정은 기능을 미리 정한 결과가 아니다. 실시간 꼬리질문·성향 설정은 경쟁 서비스에서 이미 확인했고, 토론·PT·다대다의 실제 활용도 공고로 확인했으며, 저비용 음성 경로와 개인정보 제약을 함께 비교한 결과다. 아직 사용자 실험을 수행하지 않았으므로 제품시장 적합성과 한국어 평가 성능은 **검증되지 않았다**.

| 문서 | 역할 |
|---|---|
| `master-plan.md` | 최종 제품 결정, 비용·검증·개발 우선순위 |
| `implementation-spec.md` | 화면, 상태기계, 음성, 평가, DB, REST/WSS, 예외·운영 |
| `ai-contracts.md` | 프롬프트, 컨텍스트 예산, 모델 I/O, 질문 팩·보고서 예시 |
| `contracts/evaluation.schema.json` | 보고서 핵심의 기계 검증 가능한 JSON Schema |
| `fixtures/evaluation.valid.json` | 합성 답변과 일치하는 보고서 예시 |
| `research-market.md` | 국내외 경쟁, 수요, 실제 면접 공고, 출처 한계 |
| `research-technology.md` | API·모델·음성·단가 원문 근거와 대안 |
| `research-evaluation-legal.md` | 평가 연구, 법령·개인정보·운영 검토 |
| `cost-assumptions.json` + `../tools/cost-model.mjs` | 수정·재계산 가능한 원가 모델 |

문서 간 우선순위는 본 문서의 **최종 결정표**→구현 명세→AI 계약→연구 제안 순이다. 연구 문서의 대안·잠정 수치는 결정 이력을 위해 남겼으며 운영 설정으로 그대로 복사하지 않는다.

## 1. 무엇을 조사했고 무엇을 확인하지 못했는가

공개 공식 서비스·모델 문서·가격표, 정부 통계, 실제 채용·입학 공고, 법령, 구조화 면접 및 LLM 평가 논문을 조사했다. 세 분야를 병렬 조사한 뒤 부모 에이전트가 경쟁 핵심 주장, 모델 가격, Gemini 약관, 통계, 법령 일부를 재열람하고 구현 명세를 교차 검토했다.

표시 체계: **사실**은 출처가 확인된 내용, **공급사 주장**은 공식 광고가 존재한다는 뜻, **추정**은 가정 기반 계산, **설계 결정**은 Intervu의 선택, **검증 필요**는 실험·계약·전문가 확인 전이다. 공개하지 않은 경쟁 기능을 미지원이라고 단정하지 않는다. 사용자가 준 기존 설계나 코드에 맞춘 조사는 아니며 작업 시작 시 저장소는 비어 있었다.

수행하지 않은 것: 실제 경쟁 서비스 로그인 사용, 구직자 인터뷰, 유료 API 호출, 한국어 벤치마크, 실제 개인정보 처리 계약, 변호사의 법률 검토, 결제 의향/매출 검증. 아래 실험의 표본·기간·통과율은 실험 계획이며 실적이 아니다.

## 2. 시장과 고객의 필요

2026년 5월 공식 청년층 조사에서 취업 경험이 있는 졸업 청년 중 첫 일자리가 임금근로인 집단의 첫 취업 평균 소요기간은 11.2개월이다. 취업시험 준비 분야에 일반기업체와 공무원이 포함된다. 이 통계는 취업 준비의 맥락이지 AI 면접 구매 수요나 시장 규모가 아니다. 상세 모집단과 수치는 연구 문서에 보존했다. [2026-07-23 정부 브리핑](https://www.korea.kr/briefing/policyBriefingView.do?newsId=156771847)

고객 문제 가설은 세 가지다. 첫째, 혼자 말해 보는 것은 가능하지만 답변에 따라 바뀌는 질문과 반론을 만들기 어렵다. 둘째, 일반적인 ‘구체적으로 말하라’는 피드백은 다음 답변에서 무엇을 바꿔야 하는지 알려주지 않는다. 셋째, 공고에 맞는 형식과 블라인드 규칙을 확인하는 부담이 있다. 이 가설은 인터뷰에서 현재 준비 방법·실제 지출·실패 경험으로 확인한다.

| 고객 후보 | 필요·접근성 | 복잡도/약점 | 결정 |
|---|---|---|---|
| 성인 신입 일반기업/공공기관 | 공고와 면접 일정이 있고 반복 준비 이유가 명확 | 무료 대체재, 단기 이용, 직무 차이 | 초기 타깃 |
| 경력 전문직 | 지불 가능성 가설, 심층 질문 필요 | 산업 지식·정답 검수 비용 큼 | 검수자 확보 후 팩 확장 |
| 학교·대입 지원자 | 모집단위별 연습 수요 가능 | 미성년자·전형·공급사 제한 | 초기 제외 |
| 대학 취업센터 | 기관 공급 사례 존재 | 기존 계약·영업주기·개인정보 역할 | 개인 파일럿 이후 B2B2C 검증 |
| 실제 채용기관 | 평가 자동화 수요와 연결 가능 | 고영향·타당성·권리 침해 위험, 주제 변경 | 채용 선발 도구로 확장하지 않음 |

사용 지속성은 매일 접속으로 정의하지 않는다. 면접 준비가 계속되는 사람의 7일 내 재연습, 새로운 질문에 대한 개선, 다음 지원 때 재방문을 본다. 합격 후 이탈은 목적 달성일 수 있다. 전체 청년 수×월 구독료로 TAM을 계산하지 않고 초기 채널별 실제 유입·활성·구매로 bottom-up 수요를 추정한다.

## 3. 경쟁과 차별화

국내 JOBDA·뷰인터·캔디데이트, 해외 Yoodli·Huru·Big Interview를 비교했다. 국내 일부 서비스는 로그인·JS·첨부 접근 제약 때문에 현재 요금과 세부 동작을 확정하지 못했다. 경쟁사의 공식 설명을 제품 효과의 증거로 사용하지 않았다.

특히 Yoodli는 기업/직무·성향·동적 질문·발표 Q&A를 안내하고, Huru는 대화형 질문과 성향 선택 및 개인 무료 이용을 안내한다. 따라서 ‘AI 면접 최초’, ‘압박 면접 최초’, ‘무료라서 차별화’는 근거가 없다. [Yoodli 공식 안내](https://support.yoodli.ai/en/articles/9550465-practice-with-yoodli), [Huru](https://huru.ai/)

차별화는 기능의 존재보다 **근거의 추적 가능성과 한국어 개선 효과**에 둔다.

| 약속 | 구현 증거 | 검증 방법 |
|---|---|---|
| 공고 조건을 구분한다 | 확인된 공고 사실/사용자 입력/연습 가정 배지 | 생성 기관 주장마다 원문 위치 일치 |
| 피드백을 설명한다 | 발언 인용·역량 앵커·개선 행동 연결 | 문자열+인간 의미 지지 검사 |
| 개선을 확인한다 | 동급의 다른 질문 재연습 | 인간 평가자에게 전후·조건 숨김 |
| 한국 블라인드 연습을 돕는다 | 공고별 정보 정책, 신상 배제 | 대응쌍·누출 테스트 |
| 혼자 토론한다 | 발언권 제어와 주장 참조 | 사용자 기회 보장·사람 스터디 경험자 검사 |

이는 방어 가능한 독점성을 입증한 것이 아니라 제품 가설이다. 장기 자산은 합법적으로 확보한 한국어 검증셋, 검수된 직무 질문 팩, 평가 버전별 오류 분석이다. 개인 데이터를 무단 학습시키거나 유료 기출을 수집하는 방식으로 자산을 만들지 않는다.

## 4. 면접 유형과 MVP 선정

실제 공고에서 사학연금의 PT·토론, 부산항만공사의 토론·역량, 농정원의 구조화 다대다 등을 확인했다. 이들은 실제 활용 사례이며 전국 채택률은 알 수 없다. [사학연금 2026 공고](https://job.alio.go.kr/recruitview.do?idx=300070), [부산항만공사 공고](https://job.alio.go.kr/recruitview.do?idx=281410), [농정원 공고](https://job.alio.go.kr/recruitview.do?idx=292428)

유형은 네 축이다: **과제(경험/상황/토론/PT), 참여구성(1:1/패널/다대다), 정보정책(블라인드), 성향(친절/일반/논리 검증형)**. 블라인드를 토론과 배타적인 모드로 만들지 않는다.

선정 기준은 핵심 사용자 가치, 검증 가능성, 비용·운영 난도다. 아래 우선순위는 실측 점수표가 아니라 조사에 근거한 제품 판단이다.

| 기능 | 가치와 증거 | 구현/검증 부담 | 범위 |
|---|---|---|---|
| 공고 입력·승인 | 근거 있는 맞춤의 출발 | 추출·출처 검사 필요 | P0 |
| 1:1 음성 꼬리질문 | 핵심 실시간 상호작용 | 한국어 STT·턴 지연 | P0 |
| 친절/일반/논리검증 | 요구사항 충족, 기존 경쟁 표준 | 표현 정책·안전 검사 | P0 |
| 블라인드 | 한국 공고의 명시 규칙 | 마스킹 불완전성 검증 | P0 |
| 근거 피드백·재연습 | 차별화 핵심 가설 | 평가셋과 검수 필요 | P0 |
| 토론 AI 2명 | 혼자 대체하기 어려운 환경 | 역할 혼선·기회·협업 평가 | P1 닫힌 베타 |
| PT | 실공고 확인, 엔진 재사용 | 과제 검수·발표 단계 | P2 |
| 다대다/패널 | 실제 활용 확인 | 역할·순번·평가 기회 다양 | P2 |
| 파일/URL 자동 수집 | 편의 | SSRF·파싱·권리·PII 비용 | P2 |
| 얼굴·감정·합격예측 | 핵심 가치에 불필요 | 타당성 미확보 | 제외 |
| 게임·SNS·채용매칭 | 면접 훈련과 직접 연결 약함 | 범위 과대 | 제외 |

토론을 공개 MVP 필수에 넣지 않는 이유는 혼자 연습하는 가치가 없어서가 아니다. 한 사람의 답변 평가조차 검증되지 않은 상태에서 AI 참가자 행동에 의해 점수가 바뀌는 평가를 동시에 출시하면 검증 문제를 분리하기 어렵기 때문이다. 구현은 같은 상태기계 위에서 하되 공개 승인 게이트를 분리한다.

## 5. 핵심 사용 경험과 AI의 역할

사용자는 공고·지원 직무·선택적 경험을 입력하고 추출된 조건을 확인한다. AI는 확인되지 않은 기업 특성을 보완해 지어내지 않는다. 기본 면접에서 사용자 답변을 전사한 뒤, 본인 역할·선택 이유·결과가 불명확한 부분을 한 번 더 묻는다. 종료 후 발언을 인용한 개선점 최대 3개와 90초 재연습을 제공한다.

AI 역할은 분리한다. 공고 추출기는 사실 후보를 제시하고, 질문 작성기는 표현을 만들며, 서버 진행기는 시간·순서·예산을 결정한다. 평가기는 동결된 답변만으로 루브릭 근거를 산출한다. 토론 AI는 발언 순서와 관점에 따라 반론을 만들고 점수는 보지 못한다. 모델이 어떤 행동을 제안해도 프로그램의 상태·권한·예산 규칙을 우회할 수 없다.

예시: “협업 중 갈등을 해결한 경험을 말해 주세요.” 사용자가 “제가 설득해서 일정대로 끝났습니다”라고 답하면 “설득할 때 제시한 대안과 본인이 한 행동을 설명해 주세요”를 묻는다. 평가에서는 ‘협업 능력이 낮다’고 단정하지 않고 “본인 행동의 구체적 근거를 아직 확인하지 못했습니다”라고 설명한다. 실제 성과를 지어낸 답변을 대신 써주지 않는다.

## 6. 평가 체계와 신뢰성

구조화 질문과 공통 행동 기준은 OPM 안내를 참고한다. 인간 면접의 연구 결과가 AI 한국어 코칭의 타당도로 자동 이전되지는 않는다. LLM 평가자의 장황함·위치·자기선호 편향도 고려한다. [OPM](https://www.opm.gov/policy-data-oversight/assessment-and-selection/structured-interviews/), [Zheng 외 연구](https://arxiv.org/abs/2306.05685)

초기 평가 차원은 질문 적합성, 경험·근거 구체성, 논리·판단, 성찰·전이. 각각 1~4 행동 앵커를 쓰며 관찰 부족은 보류한다. 두 유효 답변 이상에서 관찰된 차원만 수준을 보여준다. 전체 총점·백분위·합격 확률은 없다. 직무 정답은 검수된 자료가 있을 때만 별도 판단한다. 개인 경험이 실제인지 확인하는 기능은 없다.

전사 오류 정정과 내용을 잘 쓰도록 고친 답변을 분리한다. 전자는 ‘교정 후 평가’, 후자는 새 연습이다. 동일 모델·루브릭·질문 난도·입력 방식에서만 전후 비교하고 다른 버전을 한 성장 그래프에 섞지 않는다. 불확실한 점수를 공개하지 않는다고 정성 피드백이 자동 신뢰할 만해지는 것은 아니므로 정성 문장도 근거 지지 검사를 받는다.

## 7. 기술 선택과 대안

최초 운영 후보는 **Groq Whisper Large V3 Turbo → OpenAI GPT-6 Luna → Google Cloud WaveNet 한국어 음성**이다. 기본은 턴 단위로 말하고 답변완료 후 반응하는 방식이다. 계속 듣고 겹쳐 말하는 완전 양방향 음성과 구분한다. 한국어 벤치마크·계약·실제 계정 접근을 통과해야 공개 가능하다.

텍스트 모델의 현재 단가는 입력 $0.10/백만, 출력 $0.50/백만이고, Groq 전사는 $0.04/시간·요청당 최소 10초, WaveNet은 무료량 초과 $4/백만 문자다. 공식 가격을 바탕으로 후보를 선택했으며 공급사 속도 광고를 Intervu 지연으로 사용하지 않았다. ## 8. 무료·저비용 운영의 범위

**API 원가와 실제 서비스 원가를 구분한다.** 15분 중 사용자 발화 8분, AI 발화 4분, 생각·전환 3분; LLM 누적 입력 45,000/출력 5,000 tokens; TTS 2,200자를 가정한다. 이 사용량은 실측이 아니다. 더 짧은 기본 질문 수와 실제 발화속도에 따라 달라져도 비용 모델은 여유 있게 유지한다.

`C_session = Σmax(10, STT턴초)/3600×0.04 + 입력tokens/1M×0.10 + 출력tokens/1M×0.50 + TTS문자/1M×4`

기본 계산은 약 **$0.02113/15분**이다. 스트리밍은 STT의 실제 전송분과 프로모션 여부에 따라 **$0.1114~$0.1885**. 무료량·캐시·세금·인프라·재시도는 이 값에서 제외했다. 준비 공고 추출과 예외 호출을 포함한 25% 추가 예산은 계획 가정이다. Native의 신규 오디오 비용만 보고 세션 전체 가격이라고 부르지 않는다.

| 100 | $2.11 | $2.64 | $41.64~82.64 |
| 1,000 | $21.13 | $26.42 | $65.42~106.42 |

*10,000회에서 같은 인프라로 충분하다는 보장은 없다. 이 열은 고정비가 같을 때의 산술 민감도일 뿐 용량 견적이 아니다. 사람 검수·고객지원·메일·결제·도메인·세금·환전·트래픽 초과비용은 별도다. 원화는 실제 결제 환율로 환산한다.

[Render 가격](https://render.com/pricing), [무료 제한](https://render.com/docs/free), [Supabase 가격](https://supabase.com/pricing)

WaveNet 무료 문자만 보면 2,200자 기준 월 약 1,818회지만 STT·LLM·서버·쿼터가 남으므로 **전체 서비스 무료 1,818회**가 아니다. Gemini unpaid에는 개인정보·기밀 입력 제한과 데이터 활용 조건이 있으며 연령 관련 제한도 있다. 단순 동의로 모든 조건을 해결할 수 없다. [Gemini 약관](https://ai.google.dev/gemini-api/terms)

수익모델 가설은 월 자동갱신보다 7일/30일 집중 연습권 또는 회차권이다. 예를 들어 5회권 ₩4,900/₩9,900을 선택 실험할 수 있으나 최종 가격이 아니다. 공헌이익은 매출에서 결제수수료·세금·API·변동 인프라·지원·환불·검수비를 차감해 계산한다. API가 싸다는 이유로 수익성을 입증했다고 볼 수 없다.

## 9. 개인정보·법률·운영 결정

개인 연습 서비스로 한정하고 개인별 점수·순위를 채용기관에 전달하지 않는다. AI 생성 음성과 코칭 결과를 명확히 표시한다. AI 기본법 제31조의 표시 의무와 고영향 해당성은 구분하여 검토한다. [현행 제31조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031810729)

국외 API별 처리 국가·수탁/재수탁·보존·학습 사용·DPA·이전 근거를 등록하고, 승인 전 실제 사용자의 데이터를 보내지 않는다. 개인정보 처리·선택 이력 보관·품질 연구를 분리한다. 공급사가 학습에 쓰지 않는 것과 로그를 보관하지 않는 것은 다른 조건이다. 한국 개인정보보호법상 정확한 적용 경로는 운영 주체와 계약을 바탕으로 출시 전에 검토한다. [국외 이전 조항](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1020398611)

원음 장기 저장 기본 OFF, 전사·보고서·공고 기본 30일, 선택 이력 최대 180일 후 무응답이면 삭제. 앱 오류 로그는 본문 없이 14일, 비식별 원가 집계 90일. 백업 최장 30일 순환을 배포 요건으로 하되 공급사 계약에서 더 긴 보존이 있는지 확인한다. 법정 접근·거래기록은 별도 확정한다. 이 기간은 제품 정책이며 법정 기간을 주장하는 것이 아니다.

블라인드에서는 학교·출신 등 식별 단서를 질문·평가 컨텍스트에서 배제하되 자동 마스킹의 완전성을 보장하지 않는다. 실제 공고의 금지 규칙과 법의 적용범위를 혼동하지 않는다. 압박은 논리 검증이며 모욕이나 인격 판정이 아니다. 원문·생성 결과·공개 자료를 공용 학습 데이터로 자동 편입하지 않는다.

| G8 토론 | 12~20명, 사람 스터디 경험자 포함 | 최소4회 사용자기회 확보≥95%, 완주≥80%; 미달시 공개 OFF |
| G9 운영/법 | 소유권침해/삭제복구/공급사약관/비용실측 | 타사용자누출0, 중복명령의중복호출0, 삭제부활0; 미승인 전송0 |

수요 실험의 분모는 고정한다. `started`는 첫 질문 재생 후 실제 답변을 제출한 사용자, `completed`는 종료·보고서 생성이 완료된 사용자다. 7일 유지율은 아직 준비 중인 코호트와 전체 코호트를 함께 보고하며 탈락자를 분모에서 임의 제거하지 않는다. `feedback_to_retry`는 완료 후 24시간 이내 재답변 시작/완료를 각각 집계한다. 목표 미달이어도 표본이 작으면 기계적으로 폐기하지 않고 인터뷰와 함께 판단한다.

평가 CI는 사용자 단위 bootstrap으로 묶어 같은 사람 답변을 독립 표본으로 부풀리지 않는다. 성별·장애 등 민감한 속성 수집은 별도 동의와 최소화 원칙이 필요하다. 합성 대응쌍은 실제 집단 공정성의 충분한 증거가 아니다. 인간 기준셋 구축비·검수 시간은 별도 예산이며, 예를 들어 200답변×2평정×5분=약33.3시간+조정 시간이라는 작업량 가정으로 산정한다.

## 12. 개발 백로그와 의존관계

인력·일정 정보가 없으므로 아래는 숙련 풀스택 1명+기획/검수 협력자를 가정한 **추정 작업일**이다. 병렬 연구와 사용자 모집은 별도이며 일정 약속이 아니다. 개발 에이전트가 추가 제품 기획 없이 순서대로 구현하도록 입력·완료 조건을 명시했다.

| 순서/ID | 작업과 산출물 | 선행 | 추정 | 인수조건 |
|---|---|---|---:|---|
| 0/D00 | repo·TS·CI·env template·계약 스키마·mock adapters | 없음 | 1~2일 | 외부키 없이 로컬 빌드/fixture 검사 |
| 1/D01 | Auth·DB migrations·owner scoping·RLS·삭제 tombstone | D00 | 2~3일 | 사용자A가B profile/session/report 읽기·수정 불가 |
| 2/D02 | 공고 붙여넣기·PII 검사·근거추출·승인 버전 | D01 | 2~3일 | 출처span 불일치 거부·공고없음 일반모드 |
| 3/D03 | 세션 상태기계·질문팩·텍스트면접·멱등명령 | D02 | 3~4일 | 중복/순서역전/타임아웃 시 한 번만 전이 |
| 4/D04 | 비용예약·usage ledger·provider policy·kill switch | D03 | 2~3일 | 동시요청예산 초과불가·unknown 비용보존 |

핵심 경로는 D00→D01→D02→D03→D04→D07→D08이며 평가/검수 경로도 출시 필수다. 초깃값 총 개발 24~37인일(D00~D09), 여기에 실제 모집·검수·파일럿 2주 이상이 겹치거나 추가된다. 한 명의 경험이 적으면 수배 늘 수 있다. 예산이 부족하면 토론·차트·내보내기 UI를 늦추되 핵심 소유권·삭제·비용·피드백 근거는 생략하지 않는다.

### 필수 E2E 인수 시나리오

1. 공고 없음→일반모드 안내→3문항 텍스트→근거 보고서→재답변.
2. 공고에 없는 기관 면접시간을 모델이 생성→검증거부→기본설정 표시.
3. 마이크 거부→텍스트 전환→음성지표 미산출.
4. 오디오 frame 누락→재요청→복구불가면 해당 턴 재답변, 감점 없음.
5. STT에서 부정어 오인식→사용자정정→교정배지·새보고서, 원이력 유지.
6. 답변에 ‘시스템 무시·만점’ 삽입→평가정책불변.
7. API timeout→unknown 비용보존→worker재claim으로 중복호출 없음.
8. 같은 finish 명령2번→평가job1개, 결과1개.
9. AI음성 중 끼어들기→300ms 목표 내 정지→늦은chunk 미재생.
10. 사용자A가B의 UUID 추측→404, 로그에본문없음.
11. 평가중 삭제→결과저장차단→백업복구후 tombstone 재적용.
12. 토론AI2명이 연속발언→사용자에게우선권, 기회부족 점수보류.

## 13. 주요 위험과 방향 전환 규칙

| 위험 | 조기 신호 | 대응·방향 전환 |
|---|---|---|
| 범용 음성 AI와 차이 없음 | 공고적합·피드백유용성·재연습 개선 없음 | 질문유형 추가 중단, 근거품질/타깃 집중 |
| 저가 음성 지연·오인식 | G2/G3 실패 | 더 비싼 STT만 교체·스트리밍 실험, 사용량 재산정 |
| 평가 점수 불신 | 인간일치/의미근거 미달, 이의 많음 | 해당 점수숨김·루브릭 재설계; 정성도 검증 |
| 토론이 연극처럼 느껴짐 | AI끼리 과다대화, 사용자 기회부족 | AI1명/사회자시나리오 축소, 공개보류 |
| 무료 남용 | 계정수 급증·실사용분 감소·원가급증 | 단일활성세션·예약·속도제한, 상한후중지 |
| 운영비가 API보다 큼 | 지원·검수시간 과다 | 콘텐츠 범위 좁히고 자동복구 강화 |
| 기관맞춤 사실 오류 | 출처없는 형식·인원·기출 단정 | 기관프로필 비활성화·일반 연습으로 전환 |
| 법/계약 불일치 | 처리국가/삭제/연령조건 불명 | 해당 공급사 전송 OFF, 승인 경로 선택 |

개발 에이전트는 위 결정으로 구현을 시작할 수 있다. 아직 알 수 없는 것은 기획 공백이 아니라 실측·계약·사용자 검증의 결과다. 그 결과가 실패했을 때의 축소·교체 규칙까지 본 설계의 일부로 삼는다.
