## 2. 시험 계획

### 2.1 자동 시험 계층
| 계층 | 도구 | 내용 | 실행 |
|---|---|---|---|
| 가드 | `npm run check:project` | PROJECT.md·AGENTS.md 구조, UI 9화면·금지 패턴 | 매 WP |
| 단위/도메인 | `node --test` | claims, documents, transfer, trends, pii, evaluation | 매 WP |
| API 계약 | `node --test`(핸들러 직접 + HTTP) | 엔드포인트·권한·삭제·관리자·게이트 | 매 WP |
| 공급자 계약 | 스텁 `fetch` | 04 §7 | B-트랙 |
| 브라우저 E2E | Playwright(`tools/e2e-ui.mjs`) | 9화면 흐름, 1440/768/390, 콘솔·예외·4xx/5xx | UI 변경 시 |
| 골든 불변식 | `tests/eval` | 04 §8 | B-트랙 |
| 보안 프로브 | 스텁 기반 오프라인 스크립트 | 위조 플래그·인젝션·삭제 잔존·무인증 접근 | 보안 WP |

### 2.2 브라우저 E2E 실행 환경 (현재 제약 — WP-E1이 해결)
- `tools/e2e-ui.mjs`는 `playwright` 모듈(환경변수 `PLAYWRIGHT_MODULE` 또는 npx 캐시)을 찾고 브라우저 빌드가 **Playwright 버전과 일치**해야 한다.
- 이 개발 PC(2026-10-29 점검)에서는 전역 Playwright 1.61.1과 설치된 `chromium_headless_shell-1248` 빌드가 맞지 않아, 저장소 밖 임시 래퍼가 `executablePath`를 지정해 실행했다. 이 방식은 **임시 우회**이며 문서화된 표준이 아니다.
- E2E를 실행하지 못한 WP는 보고서에 **"E2E 미실행(사유)"**을 적는다.

### 2.3 수동 시험(체크리스트)
- 접근성 점검표(06 §8) — 키보드만, 스크린리더 샘플(가능한 도구), 확대 200%, 대비.
- 모바일 실기기(iOS Safari, Android Chrome): 레이아웃, 키보드 올림, 마이크 권한, TTS 한국어 음성.
- 다른 브라우저(Firefox, Safari): 핵심 흐름 + `MediaRecorder`·`SpeechSynthesis` 지원 차이 기록.
- 장애 주입: 공급자 키 제거/오류/429/느린 응답 → 폴백 배너·진행 지속, 서버 재시작 → 복원·안내.

## 3. 비기능 목표 (측정 후 기록; 목표치는 가설)

| 항목 | 목표(가설) | 측정 방법 |
|---|---|---|
| 꼬리질문 응답 지연(live) | 사용자 체감 대기 ≤ 수 초, 타임아웃 시 폴백 | 스모크 로그 p50/p95 기록 |
| 보고서 생성(규칙 기반) | ≤ 수 초 | 서버 로그 |
| 페이지 로드(정적) | 첫 화면 즉시 표시(JS 모듈 로딩 포함) | 브라우저 성능 탭, 미실행이면 "미측정" |
| 가용성 | 데모 중 중단 없음 | 리허설 로그 |

수치는 **측정하기 전에는 성과로 쓰지 않는다.**

## 4. 사람 평가 실험 설계 (PROJECT.md §6.2; 아직 실측 결과 없음)

| 실험 | 표본·방법 | 산출 | 주의 |
|---|---|---|---|
| E-1 질문-근거 연결 | 합성/동의된 지원서 20건 이상, 질문이 실제 근거 문장에 연결됐는지 블라인드 검수 | 연결 정확도, 오류 유형 | 자소서에 없는 사실 생성 0건이어야 함 |
| E-2 평가 일치도 | 답변 20건 이상을 사람 평가자 2명 이상이 독립 채점, 규칙 기반(및 모델) 평가와 비교 | 일치도(예: 가중 카파), 불일치 사례 | 일치도가 낮으면 평가기를 "참고 관찰"로만 표기 |
| E-3 공격 시험 | 키워드 주입·프롬프트 인젝션·PII 우회·합성 플래그 위조 반복 | 성공/총 시도 수 | 결과 그대로 기록 |
| E-4 꼬리질문 적합성 | 직전 답변과의 관련성 평가 | 관련/무관 비율 | |
| E-5 전이 개선 | 같은 역량 다른 질문에서 두 번째 답변이 나아졌는지 블라인드 비교 | 개선/무변화/악화 | **인과 주장 불가**(대조 설계 필요) |
| E-6 STT | 한국어 음성 합성/동의 샘플의 CER/WER, 지연 | 오류율 | 샘플 수·환경 명시 |

각 실험은 **표본 수·방법·결과**가 모두 있어야 "검증됨"이라 쓸 수 있다. 결과가 없으면 "미실행".

## 5. 장애 대응 계획 (데모 중)

| 상황 | 대응 |
|---|---|
| 외부 AI 지연·실패·한도 | 앰버 배너와 함께 기본 질문으로 계속(폴백). 시연자는 "Mock로 대체됨"을 말로도 설명 |
| 서버 재시작/데이터 소실 | 영속 저장(A2)이 있으면 복원, 없으면 샘플 재로드 후 단계 6부터 재시작 |
| 마이크 권한/브라우저 미지원 | 텍스트 입력으로 진행(음성은 선택 단계) |
| 네트워크 단절 | 로컬 Node 서버+`STORE=file`로 사전 준비된 백업 실행(DG-1 대안 B) |
| 실모델 키 만료·결제 이슈 | `LLM_*_PROVIDER=mock`로 전환해 시연(모드 칩이 Mock로 바뀌는 것을 보여 줌) |

## 6. 리허설·체크리스트 (WP-E3)

- [ ] 깨끗한 환경에서 설치(의존성 없음)→실행→접속 토큰 입력→시나리오 1~12 완주 (2회 이상)
- [ ] 고입·대입 양 경로(구 기업·대학), 데스크톱·모바일 폭
- [ ] 모든 비밀(`.env`)이 저장소·화면·로그·스크린샷에 없음
- [ ] 공급자 모드 표시 vs 실제 호출 로그 일치(Mock을 live로 표기한 적 없음)
- [ ] 금지 표현 0건(합격 예측·점수 순위 등), 평가기 칩 정확
- [ ] 삭제 후 잔존 없음, 내보내기에 키 없음
- [ ] 백업 플랜(§5) 각각 1회 시연
- [ ] 리허설 로그(날짜·환경·결과·미해결)를 `docs/validation-results.md`에 사실대로 기록
