# Intervu — 프로젝트 소개서

> **지원 공고의 확인된 조건으로 연습하고, 내 발언을 근거로 피드백받은 뒤, 다른 질문에서 개선을 확인하는 한국어 AI 모의면접 코치**
>
> 기준일: 2026-10-27 · 상태: MVP 구현 완료, 시장성·성능 검증 전

---

## 1. 한눈에 보는 Intervu

| 항목 | 내용 |
|---|---|
| 제품 | 한국어 AI 모의면접 연습 서비스 (웹) |
| 대상 | 만 19세 이상, 30일 내 면접을 앞둔 신입 구직자 (일반기업·공공기관) |
| 한 줄 약속 | "합격 확률은 말하지 않습니다. 다음 답변에서 바꿀 행동 하나를 정해줍니다." |
| 핵심 흐름 | 공고 입력·승인 → 10/15분 면접(텍스트) → 근거 인용 보고서 → 90초 재연습 |
| AI 공급자 | Gemini 우선 (`gemini-3.5-flash-lite`), Mock-first 게이트 |

| 하지 않는 것 | 합격 예측·백분위·성격/감정 진단·얼굴 분석·채용기관 점수 전달 |

## 2. 배경과 문제 정의

면접 준비생이 겪는 세 가지 문제를 가설로 세웠다 (사용자 인터뷰로 검증 예정, G0 게이트):

1. **바뀌지 않는 질문** — 혼자 말해 보는 것은 가능하지만, 답변 내용에 따라 바뀌는 꼬리질문과 반론을 혼자 만들기 어렵다.
2. **행동으로 안 이어지는 피드백** — "구체적으로 말하라"는 피드백은 다음 답변에서 무엇을 바꿔야 하는지 알려주지 않는다.
3. **형식 확인의 부담** — 공고에 맞는 면접 형식과 블라인드 규칙을 매번 확인해야 한다.

이 가설이 사실이라면, 필요한 것은 '더 많은 기출'이 아니라 **내 발언을 인용해 다음 행동을 짚어주는 코치**다. Intervu는 그 가설 위에 설계됐다.

---

## 3. 타깃 사용자

- **1순위**: 만 19세 이상 한국어 신입 구직자 (일반기업·공공사무 중심, 면접 일정이 있거나 집중 준비 중)
- **제외**: 미성년자·대입 지원자 (연령·공급사 제약), 실제 채용기관의 선발 평가 용도 (고영향 위험이므로 확장하지 않음)
- **지표 정의**: 매일 접속이 아니라 "7일 내 재연습", "새 질문에서의 개선", "다음 지원 때 재방문"을 본다. 합격 후 이탈은 목적 달성일 수 있다.

## 4. 핵심 기능

### 4.1 사용자 흐름 (3단계 + 보고서)

1. **지원 정보 입력** — 기관·직무·공고 본문·경험 메모 (공고 없이도 일반 연습 가능)
   - 전화·이메일·주민번호 자동 마스킹, 추출 결과에 원문 위치(span) 표시
   - "확인된 기관 고유 역량 없음"이면 '일반 템플릿' 배지로 정직하게 표시
2. **추출 결과 승인** — 모델이 추출한 역량 후보를 사용자가 확인·승인해야 세션 생성 가능
3. **면접 설정 후 시작** — 10/15분, 성향 3종(친절형/일반형/논리검증형), 블라인드 ON/OFF
   - 오른쪽 **라이브룸**에서 질문 → 답변 → 꼬리질문 진행 (남은 시간·진행률·예산 상태 표시, 일시정지·질문 낭독·복사 지원)
4. **근거 기반 보고서** — 4개 역량(질문 적합성·경험 구체성·논리 판단·성찰 전이)별 수준 + 발언 인용 + "다음에 할 행동 하나" + 90초 재연습

### 4.2 평가 원칙 (신뢰 설계)

- 전체 총점·백분위·합격 확률 **없음**. 차원별 1~4 수준만, 유효 답변 2개 미만이면 **판단 보류**
- 모든 평가는 사용자 발언의 **정확한 인용 + 원문 구간**을 동반. 인용 불일치는 서버 검증에서 거부
- 전사 교정(`stt_correction`)은 새 revision으로 기록, 내용 다시쓰기(`content_rewrite`)는 별도 연습으로 분리 — 원기록을 덮어쓰지 않음
- 이의제기 접수 (stt/사실/근거/부적절 유형, 처리 목표 3영업일)

### 4.3 개인정보·윤리 경계

- 원음 서버 장기 저장 안 함, 보고서·전사 기본 30일 보관, 삭제 요청 시 즉시 파기 (백업 최장 30일)
- 블라인드 모드: 학교·출신·성별·연령 단서를 질문·평가에서 배제 (마스킹 불완전성은 고지)
- Gemini 무료 할당량은 학습·인간 검토 대상이므로 **실제 사용자 데이터 전송 차단** (`GEMINI_PAID_ACK=true` 전까지 Mock 동작)

## 5. 차별화: "근거의 추적 가능성"

경쟁 서비스에도 AI 면접·성향 선택·동적 질문은 이미 있다. 그래서 Intervu는 기능의 유무가 아니라 **약속과 증거**로 차별화한다:

| 약속 | 구현 증거 |
|---|---|
| 공고 조건을 구분한다 | 확인된 공고 사실 / 사용자 입력 / 연습 가정 배지 분리, 출처 문장 위치 표시 |
| 피드백을 설명한다 | 발언 인용 + 역량 앵커 + 개선 행동 연결 |
| 개선을 확인한다 | 동급의 다른 질문으로 재연습, 원래 점수를 덮어쓰지 않음 |
| 블라인드 연습을 돕는다 | 공고별 정보 정책, 신상 단서 마스킹 |

## 6. 기술 개요

- **스택**: 외부 라이브러리 없이 Node.js 20+ 단일 프로세스 (HTTP REST + 정적 SPA). DB는 인메모리 저장소 (Postgres·RLS는 후속 범위)
- **상태 기계**: 세션 `ready → active ↔ paused → completing → completed`, 삭제(`deleting → deleted`)가 최우선
- **예산 원장**: 호출 단위 예약·정산. 세션 상한 $0.08, 평가 예약 $0.02 포함. 원인 불명 비용(unknown)은 자동 반환·재호출 금지
- **멱등성**: 쓰기 요청 `Idempotency-Key` 필수, 동일 `command_id`+다른 본문은 409
- **Provider 게이트**: 키가 있어도 유료 확인 전까지 Mock. 킬 스위치(`KILL_PROVIDERS=gemini`)로 외부 호출 강제 차단 가능
- **MVP 음성**: 텍스트 면접 + 브라우저 TTS 낭독. 서버 STT/TTS 파이프라인은 어댑터 계약만 유지

### API 요약

- `POST /profiles` → 추출 → `POST /profiles/:id/approve` → `POST /sessions` → `POST /sessions/:id/connect`(일회성 티켓) → `commands(session.start/turn.text/session.finish)` → `GET /sessions/:id/report`
- 부가: `POST /turns/:id/revisions`(교정), `POST /evaluations/:id/appeals`(이의), `POST /practice-attempts`(90초 재연습), `POST /exports`(JSON 내보내기), `DELETE /sessions/:id`, `DELETE /account`

- **다음 게이트**: G0(사용자 인터뷰 30명) → G1(40문항 3인 검수) → G2/G3(음성 CER·지연) → G4/G5(인간 일치도·근거 지지) → G6/G7(제품·학습 효과)
