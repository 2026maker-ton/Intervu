## 2. 만든 이유

면접 준비생은 (1) 답변에 따라 달라지는 꼬리질문을 혼자 만들기 어렵고, (2) "구체적으로 말하라" 같은 피드백이 다음 행동으로 이어지지 않으며, (3) 지원한 전형의 면접이 어떤 방식인지 확인하기 번거롭다. 이 세 가지는 가설이며 사용자 인터뷰로 검증하기 전이다. Intervu는 "더 많은 기출"이 아니라 내 지원서와 답변을 인용해 다음에 바꿀 점을 짚어 주는 코치를 목표로 한다.

## 3. 사용 흐름

1. **입장·가입**: (설정 시) 입장 비밀번호 → 이메일·비밀번호 가입(이름, 만 18세 이상 확인, 음성 전송 고지 동의).
2. **지원 정보**: 샘플 10곳(실제 대학명 + 예시 설명, 가상 지원서) 불러오기 또는 직접 입력. 개인정보 후보는 마스킹한다.
3. **근거 확인**: 지원서 주장 추출, 학교 자료 분석(인재상·역량, 원문 인용), 학교·전형 검색(Gemini, 미검증 표시)이 자동으로 돈다. 렌치로 역량·면접 형태를 직접 고치고 새로고침 아이콘으로 다시 분석한다. 승인하면 질문 5개와 연결 문장이 고정된다.
4. **면접**: 면접실에는 질문만 보인다. 질문 낭독이 끝나면 자동 녹음, 말한 뒤 3초 정적과 문장 종결로 답변이 끝나며, 질문당 60초가 지나면 "네, 거기까지만 말해주시면 될 것 같습니다."로 끊는다. 꼬리질문은 질문당 최대 1개(도입·마무리 제외).
5. **결과**: 질문별 참고 점수, 학교 역량 적합성, 차원 레이더, 음성 지표(답변별 음량 그래프와 답변·정적 구간), 질문·답변 본문(`i` 버튼으로 근거), 다음 연습 행동 최대 3개.

## 4. 신뢰 설계

- 총점·백분위·합격 확률 없음. 차원별 1~4 수준만, 근거가 부족하면 `판단 보류`(`insufficient_evidence`).
- 모델 출력은 서버가 다시 검증한다: 원문에 없는 인용, 근거 없는 숫자·고유명사, 점수·합격 표현은 버리고 규칙 기반 템플릿으로 대체한다.
- AI가 실패하거나 게이트에 막히면 규칙 기반으로 계속하고(`provider_trace`에 표시), 다른 유료 공급자로 조용히 바꾸지 않는다. Mock은 실제 AI로 표시하지 않는다.
- 원음은 서버에 저장하지 않는다(전사용으로 Groq에 전송, 30일 보관·미국 처리 고지). 목소리 떨림·정적 분석은 브라우저 안에서만 계산하고 숫자만 저장한다.
- 학교·전형 검색 결과는 사용자 프로필에만 150일 보관하며 질문 근거로 쓰지 않는다.

## 5. AI 공급자 배치

| 작업 | 공급자 |

## 6. 기술 개요

- Node.js 20+, 외부 라이브러리 없음. 프런트는 순수 HTML/CSS/JS(7화면 해시 라우터).
- 저장소: 서버 실행은 파일(`data/store/`), 테스트는 메모리, Vercel은 Upstash Redis.
- 배포: Vercel(정적 `public/` + 함수 `api/handler.js`). Pages·Workers 어댑터는 코드만 있고 미검증([`deploy-vercel.md`](deploy-vercel.md)).
- 인증: 이메일 로그인(PBKDF2-SHA256, 토큰은 해시만 저장, 7일). 데모용 입장 비밀번호는 서버가 `/api` 전체를 잠근다.
- 멱등성: 쓰기 요청에 `Idempotency-Key`, 질문·근거는 승인 시 동결, 예산 원장으로 호출 단위 예약·정산.

## 8. 로드맵

- 보류: 특수 면접 5종, `{이름}` 치환(이름을 AI에 보내지 않고 TTS 직전 복원), 재연습·전이 비교 재도입, 이메일 인증, Workers 로그인 연결.
