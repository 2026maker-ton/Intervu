## 1. 이 기획서의 지위

우선순위(위가 이긴다):

1. 적용 법령·공급자 약관·사용자(개발자) 명시 지시·필수 보안/개인정보 요건
2. 루트 **`PROJECT.md`** (제품 방향의 단일 진실 원천, §5 보안 불변 조건 포함)
3. **이 기획서(`docs/plan/*`)** — PROJECT.md를 구현 가능한 작업 단위로 풀어 쓴 것
4. 기존 `docs/*`(과거 기획·ADR) — 이력. 충돌하면 위를 따른다.

이 기획서와 PROJECT.md가 충돌하면 **PROJECT.md가 맞다.** 충돌을 발견하면 임의로 해결하지 말고 보고서에 적는다.

## 3. 하위 에이전트 공통 규칙 (모든 WP에 적용)

### 3.1 시작할 때
1. `PROJECT.md`와 `AGENTS.md`를 **전부** 읽는다. 읽지 못하면 제품 코드를 수정하지 않고 보고한다.
2. 자신의 WP 항목(`07-work-packages.md`)과 그 WP가 가리키는 문서만 추가로 읽는다.
3. `git log --oneline -5`, `git status`로 기준을 확인하고, **WP마다 별도 브랜치/워크트리**에서 작업한다(`isolation: worktree` 권장).
4. 계획을 한 줄로 적는다: 현재 단계(P0~P5), 만족시킬 요구사항 ID, 건드릴 파일, 추가할 테스트.

### 3.2 작업하는 동안
- **가장 작은 안전한 변경**을 한다. 요청 범위 밖 리팩터링·기능 추가 금지.
- 실패 사례 테스트를 **먼저** 쓰고(수정 전 코드에서 실패하는지 확인), 그다음 구현한다.
- 기존 안전 불변 조건을 약화하지 않는다(`05-security-privacy.md`). 테스트가 불편하다는 이유로 가드를 풀지 않는다.
- 외부 API를 **호출하지 않는다**(스텁 `fetch` + 가짜 키). 실호출은 개발자가 명시적으로 승인한 스모크 도구에서만, 합성 데이터로만 한다.
- 새 의존성(npm 패키지)을 **추가하지 않는다.** 필요하면 멈추고 사유·대안·크기를 보고해 승인을 받는다.
- 코드를 쓸 때는 주변 코드의 주석 밀도·이름·관용구를 따른다. 사용자에게 보이는 문구는 `06-uiux-spec.md §6`의 문구 규칙을 따른다.
- 결정이 필요한 사항(`01` Decision Gate)을 만나면 **추측하지 말고** 멈추고 질문/보고한다. 기본값이 적혀 있으면 그 기본값으로 진행하고 보고서에 적는다.

### 3.3 끝낼 때 (필수)
1. `npm run check:project` 와 `npm test` 실행. UI/사용자 흐름을 건드렸다면 브라우저 E2E도 실행(`tools/e2e-ui.mjs`, 환경 제약은 `08` 참조). **실행하지 못한 검사는 "미실행"으로 적는다. PASS로 쓰지 않는다.**
2. 자신이 소유한 `PROJECT.md` 행(§7.2 기능 상태, §11 버그, §12 로드맵, §17 변경 요약)만 갱신한다. 다른 WP의 행은 건드리지 않는다.
3. 아래 **보고 형식**으로 최종 보고한다.

### 3.4 보고 형식 (고정)
```
WP: <ID> <이름>
요구사항/섹션: <PROJECT.md §, 이 기획서 §>
변경 파일: <목록>
추가·수정 테스트: <이름과 수정 전 실패 여부>
실행 결과: check:project <n/n>, npm test <pass/fail>, E2E <n ok | 미실행>
공급자 모드: Mock | 스텁 계약 테스트 | 실호출(승인됨)
남은 한계·미검증: <목록>
문서 불일치/충돌 발견: <목록>
다음 WP에 넘기는 정보: <API/스키마/주의>
```

### 3.5 하지 않는 것 (전 WP 공통)
합격 가능성 예측, 비공개 평가 기준 추정, 거짓말·성격·감정·외모 분석, 없는 경험·성과·수치 생성, 총점·백분위·순위, 카메라 감시, 무단 웹 수집, 실제 지원자 데이터의 미승인 외부 AI 전송, 유료 모델 자동 승격, Mock을 실제 AI로 표기, **실행하지 않은 테스트를 PASS로 기록**.

## 4. 용어

| 용어 | 뜻 |
|---|---|
| 주장(claim) | 지원자가 서류에 쓴 경험·성과 서술 문장. 거짓 여부를 판정하지 않는다 |
| 공백(gap) | 주장 문장에 없는 정보(역할·결과·판단 기준·수치) |
| 근거(evidence) | 원문 문장 + 문서 ID + 코드포인트 구간 + 출처 상태 |
| 전이 확인(transfer check) | 같은 역량을 묻는 **다른 질문**에서 두 번째 답변을 같은 루브릭으로 비교 |
| Mock | 외부 호출 없는 규칙·정적 대체. 실제 AI라고 표기 금지 |
| 합성 샘플(synthetic fixture) | 서버가 보유한 가상 지원자 자료. 클라이언트 플래그로는 만들 수 없다 |
| WP | 작업 패키지(`07-work-packages.md`) |
| DG | Decision Gate: 개발자 결정이 필요한 미확정 사항(`01`) |
